## 범위와 배포 상태

## 발견·수정한 결함

1. 저장된 목표 anchor가 실제 `syncOnce`의 회원 객체에 전달되지 않아 순수 계산 테스트와 실행 경로가 달랐습니다. 실제 경로에 연결했습니다.
2. 마스터 부분청산을 현재 자산 비율로 다시 계산하면 회원 증액이 발생할 수 있었습니다. 실제 보유 카피 수량을 같은 비율로 줄이고 보호 보유량을 유지합니다. 원래 진입이 누락됐으면 청산 이벤트로 새 진입을 만들지 않습니다.
3. 마지막 한 주문 단위와 소수점 차이가 청산에서 누락될 수 있었습니다. 거래 가능한 마지막 수량을 처리합니다.
4. Current State 저장 실패가 주문 후 비차단 처리되었습니다. 관측·엔진·Current State·anchor·intent를 원자 저장하고 일치 여부를 주문 전에 검증합니다. 양쪽 포지션이 0인 경우에도 과거 엔진 수량을 0으로 갱신합니다.
5. 여러 종목/양방향 주문이 같은 가용 증거금이나 종목 한도를 각각 사용할 수 있었습니다. 공통 예산, 종목별 총 노출과 계좌별 미확정 주문 잠금을 적용했습니다.
6. 활성 회원의 열린 주문, 주문 직전 마스터·회원 수량 변화, 주문 ID/종목/방향 불일치, DB 완료 응답 유실 경로를 보강했습니다.
7. 진입 DB 기록만으로 알림을 만들던 경로를 거래소 재조회로 검증하고 부분·전량청산 및 미체결 사유까지 확장했습니다. HTTP 200만으로 텔레그램 전송 성공을 판정하지 않습니다.

## 계산 기준

- 명목가치 기준: `회원 목표 명목가치 = 회원 자산 × (마스터 카피 대상 수량 × 동일 계약 기준가 × 계약 승수 / 마스터 자산) × 카피 비율`.
- 마스터 $20,000에서 $2,000(10%) 노출이면, 회원 $5,000·100% 카피 기준 $500(10%)을 목표로 합니다. 최소 단위·종목 한도·가용 증거금 제한을 별도로 적용합니다.
- 레버리지는 수량에 다시 곱하지 않습니다. 신규 카피는 기존 정책대로 마스터 레버리지·증거금 모드를 적용하며, 재개 전 보호 포지션의 레버리지는 변경하지 않습니다. 따라서 레버리지가 다르면 증거금 비율은 다를 수 있습니다.
- 동일 마스터 수량에서는 자산·가격 변화만으로 증액하지 않습니다. 위험 한도로 줄인 목표나 잔고 부족으로 제한된 목표는 자산 회복만으로 재매수하지 않습니다.
- 부분청산은 실제 카피 보유량(기존 목표 이내)을 남은 마스터 수량 비율로 줄입니다. 전량청산은 보호 포지션을 제외한 거래 가능한 카피 수량을 닫습니다.

## 정확성의 경계

- 보호 포지션은 카피 청산 대상이 아닙니다. 사용자의 명시적 전체 계좌 청산 요청과 구별합니다.
- 최소 주문수량 미만의 거래소 잔량을 자동으로 0으로 만들었다고 주장하지 않습니다. `execution_reason=BELOW_MINIMUM_ORDER_SIZE`로 기록합니다.
- 거래소와 DB는 하나의 원자 트랜잭션을 공유하지 않습니다. 기록 시점 일치와 이후 두 번의 체결 반영 확인을 보장하도록 설계했습니다.
- 엔진은 실제 포지션 동기화 방식입니다. 폴링 사이에 열리고 닫혀 현재 마스터에 없는 과거 거래를 뒤늦게 신규 진입으로 재생하지 않습니다.
- 텔레그램 응답/DB ACK가 유실되면 알림은 다시 전달될 수 있습니다. 주문 중복 금지와 알림의 정확히 한 번 전달을 혼동하지 않습니다.

Gate 동작 기준은 [Gate API v4 공식 문서](https://www.gate.com/docs/developers/apiv4/en/)의 Futures 주문·포지션·체결 조회 정의입니다. 실제 운영 응답과 계약 제약은 배포 후 읽기 검수에서 다시 확인해야 합니다.
